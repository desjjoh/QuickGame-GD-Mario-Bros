# Architecture

## Game and level ownership

| Owner | Responsibility |
| --- | --- |
| Game scene | Level container, title and HUD, and shared shadow composition |
| GameHandler | Session flow, stage list, player status, top score, and active-level progress |
| TitleFlow | Title screen, backdrop suspension, and new-game transition |
| StageFlow | Restart, TIME UP, Game Over, and stage-handoff operations |
| PauseController | Gameplay pause eligibility, Start toggle, tree pause, and cleanup |
| TransitionCoordinator | Covers gameplay, runs the transition operation, and restores presentation and controls |
| BaseLevel | Player spawn and death, timer lifecycle, camera boundaries, area transport, and level completion |
| AreaTransport | Destination resolution, trip state, entry and exit callbacks, and cancellation |
| LevelTimer | Countdown phase and expiry notification |
| LevelAreaContent | Painted entity population and layout/entity snapshot capture |
| LevelSpawnRegistry | Level-local capacity, occupied slots, explicit replacement, and slot release |
| LevelDeath | Level-owned death presentation, gameplay suspension, jingle, timeout, and cancellation |
| BaseLevelArea | Local layouts, camera, theme, transport metadata, and off-camera entity activity |
| AreaThemeBinding | UI-local active-area/theme subscriptions and connection cleanup |
| ControllerHandler | Global input intent |
| SoundHandler | Generated/cached cues, one-shot stream copies, and the shared reward voice |
| MusicHandler | Non-positional background playback and track changes |

Game exposes one ordered `stages: Array[PackedScene]` list. Startup validates that the list is nonempty and contains no null entries, then passes Start Stage Override or the first registered stage to the game flow. Programmatic fixtures configure `stages.assign([...])`; there is no separate first-stage compatibility property. GameHandler owns the active game, level, session, and flow state. Its TitleFlow and StageFlow children coordinate operations through the shared TransitionCoordinator. Game.title_background optionally selects the BaseLevel scene behind the title. When empty, TitleFlow uses stages[0]; the authored Game uses this fallback to show 1-1. TitleFlow reads that selection on every title entry, while the title UI owns no backdrop resource. The authored game starts at 1-1 and advances to 1-2 after the flagpole ending. Loading creates placements without implicitly activating their spawners. BaseLevel.initialize_actors establishes the area actor policy: title entry requests suspended actors, gameplay start requests active actors, and pipe arrival initializes after its transition or immediately for uncovered travel. Standalone F6 initializes at area entry. The HUD reads session values and adopts the active area’s artwork. A shared cosmetic clock keeps question blocks, coins, and the HUD coin synchronized.

The HUD and title each own an `AreaThemeBinding` child. Their parent `_ready()` connects `theme_changed` and calls `start()` after presentation references are initialized. The component follows existing level and current-area notifications, maintains one subscription to the active area's theme, emits null for missing area/theme fallback, and disconnects on tree exit. Repeated start calls do not duplicate subscriptions. Screens retain asset/font selection and their independent session-value/input handling. The HUD changes atlas artwork without restarting its shared-clock animation. The HUD shows numeric time only when the level timer is enabled and TransitionCoordinator is idle. Existing started/finished signals refresh visibility; the TIME heading follows normal HUD visibility. Countdown state is unchanged. The binding does not poll or own level/game flow.

## Area lifecycle and persistence

GameHandler exposes `is_paused`, `pause_changed`, and `request_pause_toggle()`. Its PauseController child applies SceneTree pause to gameplay and level presentations. The listener uses Always processing so Start can resume; ordinary gameplay, audio, and the shared animation clock remain pausable. SoundHandler owns a separate Always-processing pause cue player. The title screen and active transitions block pause. Level shutdown, session reset, entering Title or Detached flow, and accepted transitions clear pause.

The level scene groups its children under Areas, Players, Systems, and Presentations. Areas and Players stay in their scene order during pipe travel. AreaTransport requests the behind-world player presentation and clears it on state exit or cancellation. Systems contains LevelDeath, LevelTimer, AreaTransport, LevelAreaContent, and LevelSpawnRegistry. BaseLevel leaves Presentations empty for derived levels. 1-1 supplies FlagpoleEnding. 1-2 supplies PipeOpening, which resolves the doorway of a painted castle in the intro area for fresh entries.

Only the active area keeps its runtime layouts, objects, and camera loaded. The level captures progress on unload and applies it when that area returns. Progress belongs to the current level. BaseLevel keeps load/save/unload ordering, the duplicate-population guard, and GameHandler progress reads/writes. Its LevelAreaContent child creates painted entities and captures snapshots using one entity-name rule. The helper applies saved entity state, themes, reward overrides, transport configuration, and ending bindings; it does not load/unload runtime branches or store progress. BaseLevelArea retains runtime branch reconstruction and activity ownership. Coins and used question blocks retain their state by default, while bricks return to their active state. A level can suspend off-camera entities without destroying them, and controller input is opt-in.

Transport resolves explicit area and target IDs. A pipe handles player entry and exit presentation. The level-owned AreaTransport child validates the trip and requests the transition. BaseLevel commits player placement, the active area, and the camera handoff. The destination can be a pipe or a spawn target. Area and pipe placements share a 17-active-physics-tick arrival hold on BasePlayer. Direct placements ignore input while ordinary falling/contact continues. Animated pipe exits hold the hidden player at the configured start position for 17 ticks before emergence advances, then restore normal control immediately when the exit finishes. Tree pause and gameplay suspension freeze the countdown. 1-2 also arms the hold for early respawns at its underground entrance. Failed or cancelled travel does not grant a fresh arrival lock. New committed arrivals reset any prior countdown, and death/shutdown clear it.

In 1-2, the opening pipe uses the existing main-area player_spawn target. BaseLevel activates the intro actors at reveal and defers gameplay music and countdown until the underground drop releases input. A death after reaching the underground area uses the regular respawn path. StageFlow continues to pass the chosen entry mode through a same-level reload.

Pipe callers use `BaseLevel.can_transport()` and `transport(player, pipe.get_destination(), pipe)` for eligibility and animated travel. Scripted immediate placement retains `request_area_transfer()`. Entity generation runs through the area-loading lifecycle and its existing loaded-area guard. Counter setup uses `GameHandler.set_coins()`; gameplay coin collection uses `award_coin()` for score, sound, rollover, and extra-life rules. Reserved player/display values use their typed GameHandler methods/properties and PlayerStatus reads. `set_session_value()` / `get_session_value()` store and read generic run metadata only, including area/arrival IDs; reserved-key writes are rejected instead of creating a second value. `session_value_changed` remains the shared notification signal for typed values and metadata.

Upright pipes poll for Down after player movement. Horizontal input cancels entry when the player was grounded at the start of the tick, so Down with a direction can still enter on the landing tick. Up can be held alongside Down. Sideways pipes require grounded, right-facing contact with the lower mouth. A short body probe confirms contact with that pipe, and entry can begin with neutral directional input.

## Entities and player states

`BaseEntity` owns state-machine shutdown and exclusive one-shot playback. Level shutdown and area unload use `BaseEntity.shutdown_descendants()` to shut down entities in parent-first order, including actors nested under spawners. Each lifecycle owner decides when to save progress and unload its branches.

`BasePlayer` adds a character body and reusable movement and action nodes. Mario owns his concrete states and artwork. Movement states select behavior, while motion values carry velocity and tuning between states. Jump retains its own pose until landing, while walking off a ledge keeps the ground movement pose with animation paused.

Mario and Luigi use two terrain probes for floor support during ordinary movement. The probes sample projected feet at 5 pixels left and 4 pixels right of center. Either can accept the surface or a landing up to 4 pixels deep. A valid landing settles the body at the surface and preserves the horizontal step if the path above the corner is clear. A shallow touch at the rectangle's outer edge can clear the corner without granting support. Deep hits use the body sweep and stop horizontal movement. Walking off a ledge starts with zero vertical speed and keeps the stored fall force and Y position fraction. Godot's body still handles walls and ceilings and supplies floor contact during scripted movement.

`BasePlayer` owns the shared `Status` and `Presentation` groups. Mario places `Form` and `Damage` under `Status`, and `FormPresentation` and `WalkAnimation` under `Presentation`. `BaseEnemy` owns `Body` and `Presentation`; Goomba and Green Koopa inherit these groups. Enemy artwork, contact shapes, block-hit detection, and `AnimationPlayer` sit under `Body`, while each enemy places `WalkAnimationSync` under `Presentation`. The inherited `StateMachine` remains a separate group.

Other entity scenes follow the same ownership convention: `Body` groups physics/contact nodes, `Presentation` groups presentation helpers, and `Anchors` groups named attachment points. Blocks keep their sprite and impact query under their stationary body, with visual bounce and palette synchronization under `Presentation`. Coins group their sprite, animation player, and pickup area under `Body`. Climbables define inherited `Anchors`, `Interactions`, and `Presentation` groups. Castle and flagpole fixed artwork uses decorative `Presentation/Tiles` TileMapLayers; their moving flags and fireworks remain sprites, and collision remains separate. BaseEntity delegates startup artwork application to the stateless EntityThemeApplier helper before initializing its state machine. BaseEntity retains visual_theme, sprite, animation_player, and resolve_texture(); the helper uses that resolver for descendant sprites, per-instance tile-atlas copies, and copied texture-valued animation keys. Theme application adds no scene nodes or processing callbacks. Entity theming resolves tile-atlas textures per instance, and activity bounds include painted tile cells.

Grounded Mario filters Down plus either horizontal direction to neutral movement in both Small and Super forms. Super stands under that combination; Down alone crouches. Neutral movement retains momentum with friction, while the reference low-speed stop decision uses raw direction: Down alone or an opposing direction can stop him, but holding his movement direction preserves coasting. Airborne steering and existing crouch persistence remain unchanged.

Mario also owns `FormPresentation`, which runs growth/shrink poses through his existing form controller without replacing the actor or movement state machine. `BaseLevel.player_presentation` gates level timers and camera/gameplay advancement during the sequence. Other entities use existing gameplay suspension; cosmetic animation keeps advancing. Death, area loading, and shutdown cancel the sequence before the next lifecycle owner takes over. Super Mushroom collection invokes growth for Small Mario. Growth and shrinking reset only the sprite’s interpolation history when a pose changes its local offset, so texture and offset change together without smoothing between sizes. Shrinking applies a pending reset after the sprite becomes visible, preserving its existing damage-flashing cadence.

`power_up.tscn` supplies the shared sprite, body, and pickup area. `mushroom.tscn` adds block-hit detection, and `Mushroom` supplies walking and launch behavior for both variants. On alternating physics ticks, PowerUp checks its current pickup rectangle against the level player's current enemy-contact rectangle. It retries eligible contact after suspension, latches successful collection once, and reports consumption and grants the reward.

The Fire Flower stays in place after its 16-pixel emergence. Its four atlas cells keep the stem fixed while the top cycles every two global animation ticks. The Fire Flower, both mushrooms, and Starman share a pickup threshold of four pixels of visible rise. Small becomes Super, Super becomes Fire, and Fire remains Fire. All three Fire Flower cases use the shared delayed 1,000-point award and the power-up pickup cue.

Starman uses the same PowerUp scene and can be painted as a fixed block reward. Each area theme supplies four item frames, cycled on the global animation clock. Starman artwork rises one pixel every four ticks, reaching a 16-pixel rise on the final emergence tick. After emergence it travels at one pixel per tick, bounces using fractional vertical movement and a bottom-center probe, and reverses at walls using a leading side probe. Collection uses the power-up cue and a five-tick delayed 1,000-point award.

Mario and Luigi share a Starman status component. It blocks enemy contact damage for 35 counts of the existing 21-tick injury interval, so the exact duration depends on the pickup phase. A second star refreshes the count. The player pose cycles through the normal colors and three area palettes every two ticks, slowing to every eight ticks near expiry. The throw pose and the live movement pose use the same cached palette mapping. Pause freezes the effect. A successful pipe transfer clears Starman when the destination is committed. The flagpole presentation calls the player's on_level_end() hook when the grab is accepted, which clears Starman before descent. Falling into a pit and running out of time still cause death, which also clears the effect.

Stomps, shell kicks, injury, Starman hits, and power-up pickups share live rectangle checks on alternating physics ticks. Touching edges count as contact. The player moves before these checks. Enemies check before their own movement, and power-ups check after theirs. Starman contact takes priority over ordinary enemy contact. Walking and squashed Goombas and all Green Koopa forms use the shared knockout launch. The old pose remains visible for the hit update. Goombas reveal inverted and Koopas reveal as upright shells on the next update. Each defeat uses the smack cue and awards 100 points for a Goomba or 200 for a Koopa after five ticks.

`Mushroom` owns walking, terrain collision, gravity, and block launch motion for both variants. Both mushrooms use a center-foot probe for floor support and a leading-side probe for wall turns. The probes check painted terrain and entity bodies across the two canvases, excluding the active player body. The shared fractional vertical integrator applies the NES downward force and three-pixel integer cap, with the low half of the speed fraction retained. An accepted bump or break lifts the mushroom two pixels and captures the lifted sprite anchor with `BlockLaunchPresentation`. Horizontal movement resumes on the next physics update at the lifted height. Upward movement begins on the following update.

On an accepted player block hit, `BlockImpact` checks the center of the cell directly above on the block's canvas. A world coin there goes through the same collection, reward, and area progress path as Mario's terrain probes. The collected coin starts the shared jumping-coin presentation at its original sprite position. Coin collection and actor hits resolve independently, and a brick break awards its own 50 points.

`BlockImpact` checks live receiver rectangles at the original tile's top edge on the bonk and again after actors move while the hit is pending. The first accepted receiver consumes the hit. A normal bump stays eligible while the block bounces. A shattered brick gets its final check on the next active physics tick, before the temporary tile is removed.

`ScorePopup` owns optional rise and cleanup through `rise_and_free()`. Enemy and power-up rewards rise one pixel per tick until the HUD-height limit and display for up to 48 active physics ticks. Stomped Goomba popups expire on the second shared interval pulse, which is when the NES clears the squashed enemy slot. Callers supply the first drawn position from the pre-reaction enemy body or the collected item sprite. A shell hit on an earlier enemy slot uses the shell's X and starts the popup on the following tick. Enemy and power-up popups live under the area's WorldObjects so they can finish rising when a spawner sleeps. Area unload removes them with the rest of that area's effects. Their existing owners retain all scoring, lives, chain rules, and sound requests; showing a popup never grants a reward. Display-only `show_score()` / `show_one_up()` remain available without automatic movement or expiry. `DelayedReward` schedules an entity-selected callback after six subsequent physics updates, independently of the actor and popup. Pending awards live under the level’s Systems group, survive entity removal/activity suspension and area changes, freeze during tree pause, and are discarded on level shutdown/removal. Enemy points, enemy-chain lives, Super Mushroom points, and 1-Up lives use this delay; the life cue plays when the life is awarded. Hit reactions, chain selection, power-up effects, and the Super Mushroom pickup cue remain immediate. Coins, brick-breaking’s 50 points, and flagpole scoring keep their existing timing. FlagpoleEnding retains its coordinated popup movement, and BlockCoin retains its separate 46-tick popup phase.

Enemies call `BasePlayer.receive_damage()` for ordinary damage. Mario routes Super damage into shrinking and his `Damage` child's protection/flashing; Small damage retains the level death path. Protection uses eight 21-tick intervals, held during transformation and user pause. Injury and pipe cues share the reference sound routine. Lethal level hazards call `BaseLevel.on_death()` directly and bypass protection.

`BaseLevel.containing(node)` resolves the nearest level in the node's ancestry, including the node itself. Enemies and mushrooms opt in to `ignore_player_body(body)` during setup to exclude the current player's terrain body from their movement collisions. Their gameplay contact areas still handle damage, stomps, and pickup.

Painted spawner stamps create placements on area load. The area activates them at the camera boundary, and the placement saves consumption after the live actor is freed. The 1-Up spawner scene uses this path internally; standalone power-up painting is deferred. BaseLevel delegates its public `has_spawn_capacity()` and `try_claim_spawn_slot()` methods to LevelSpawnRegistry under Systems, retaining the shutdown claim guard. The registry tracks one live power-up and ten enemies in independent categories, removes actors on tree exit, and replaces the oldest actor only when the source explicitly requests it. Unlisted categories remain unlimited and untracked. Tracked actors receive the lowest free category-local slot when claimed: enemies use 0–9 and the power-up uses slot 0. `LevelSpawnRegistry.get_slot(category, actor)` returns that identity, or -1 for an untracked actor/category. Tree exit releases the slot; surviving actors are never renumbered. Replacement immediately reuses the freed slot while retaining the separate age-ordered list for oldest-actor replacement. BlockImpact uses category and slot order to select the first accepted block reaction. A painted spawner attempts once per area load. If the slot is occupied when the marker activates, it skips the spawn for that load. Mushroom owns terrain movement. PowerUp frees the item once its bounds are fully outside the camera cleanup region, without recording collection. A configured reward block can replace the current item. A tiered reward reads the active player form when the block releases it. Small gets a Super Mushroom, and Super or Fire gets a Fire Flower. Existing Super Mushroom reward assignments resolve as tiered. PowerUp raises the reward artwork one tile. Both mushrooms and Starman finish emergence with their bodies one pixel higher than their artwork. The bodies retain the extra clearance for the settling step.

BaseEnemy extends SpawnableEntity with a terrain body and uses the inherited entity state machine. The Goomba scene selects a shared Walking state and provides the animation and themed artwork. A painted Goomba Spawner attempts once at the camera activation boundary. The enemy category has ten live slots, separate from the one power-up slot. A failed attempt is skipped for the current area load. SpawnableEntity frees actors beyond the cleanup boundary. EnemyLayout places spawners on a 16×16 grid, with ground enemies occupying the cell immediately above their support. Defeated enemies return on death restart and area reload. BaseEnemy classifies Mario contact and validates incoming hits without assuming defeat. Concrete enemies choose reactions and explicitly call mark_defeated(hit) for permanent defeat; repeated damage or shell transitions can remain nonterminal. enemy_contact(other) identifies the contacted enemy, allowing state-specific responses. Walking retains reversal. Goomba marks its squash or knock-out state as defeated. A block knock-out applies the four-pixel position correction and first three-pixel launch step on the hit update while holding the walking sprite in place. The next update reveals the upside-down pose with its two-pixel anchor correction and resets sprite interpolation. Blocks deliver upward hits through a reusable receiver shared by enemies and mushrooms. `BlockHitReceiver.receive_hit(hit)` returns the result of its entity-provided `hit_handler` callback; a null hit or unavailable handler returns false. BaseEnemy delegates to its existing hit contract, and Mushroom reports whether its existing launch guards allowed a reaction. Eligibility, reactions, and rewards remain entity-owned. BlockImpact orders candidates by enemy, power-up, then other receiver categories. Within each category, registered actors use ascending reusable slots before unregistered actors, which use stable scene-tree order. Rejected candidates leave the hit available; delivery stops after the first accepted reaction. Unregistered actors do not claim capacity as a side effect of this ordering. Bumps and breaks share this selection path.

Enemy placements use a separate reference-based activation window: the last visible right pixel plus 48, rounded down to a 16-pixel column. Group markers represent their first member; their reference trigger is 48 pixels ahead. Both members spawn together at the last visible right pixel, 24 pixels apart. This restores reference group timing; groups do not use singles' offscreen placement rule. The authored 16×16 marker height supplies the ground-aligned actor position, with no extra pair-only Y offset. Live Goomba/Koopa actors remain active until anchor-based horizontal cleanup (73 pixels beyond the left edge; 72/73 beyond the last right pixel, including reference carry behavior). Existing vertical cleanup remains bounds-based. Resident scenery and power-ups retain the separate 64/96-pixel activity rectangles.

BaseLevel.tscn owns the shared entity_scenes registry for all standard painted entities. Derived levels inherit it without dictionary overrides; new marker mappings are added once in BaseLevel. Painted entity stamps resolve to scenes at runtime. A question block moves through Active, Bouncing, and Inactive. A hidden question block accepts a rising underside hit before becoming solid. An ordinary brick returns to Active after bouncing. Reward Brick and Reward Brick Alt inherit QuestionBlock and use static initial textures, shared reward configuration, and used-block persistence. Their Active state has no synchronized animation; the existing bounce and depletion states are inherited. Both receive a hit through the entity hit contract. Question blocks award a coin on bounce entry and create a temporary coin and score effect under the area. World coins are collected by Mario's size/posture terrain probes, not by his short support body. WorldCoin retains reward/state/persistence ownership; both coin paths use GameHandler for the coin, 200 points, and the extra life at 100 coins.

## Death and completion

BaseLevel starts its LevelTimer child after gameplay is revealed and advances it only on eligible gameplay ticks. The child updates the shared remaining time and emits expiry. BaseLevel routes expiry into visible death.

Falling below the camera triggers death without an on-screen animation. Visible death, including timeout, uses Mario’s Dead state. When BaseLevel accepts a death, it selects the restart spawn and consumes a reserve life. A level with a halfway marker and an enabled main-area camera check records the stage threshold at load. At death it compares the active camera's world-space left edge against that threshold, including in side areas. LevelDeath suspends gameplay and waits for the presentation and jingle. BaseLevel retires the player when the presentation ends and asks GameHandler to resolve the outcome once the sequence finishes. A negative reserve triggers Game Over. Otherwise StageFlow passes the spawn choice into the replacement level. An ordinary respawn uses the pipe exit's camera snap. A halfway respawn places the camera's left edge at the painted halfway line and uses that line as the main area's minimum camera X for the rest of the attempt. The main-area limit is reapplied when that area loads again. Side-area cameras use their own limits. Returning to the title clears the session while retaining the in-memory top score.

Flagpole contact starts a level-owned presentation. It handles scroll lock, descent, flag score, the castle walk, timer conversion, and the castle flag. The endpoint removes the player at the doorway. Each remaining timer unit becomes 50 points. Before conversion, the timer's final digit selects zero, one, three, or six fireworks. CastleEntity owns the burst sprite, positions, and animation, driven by CastleFireworksStep after the tiny flag rises. Each completed burst awards 500 points and requests the generated blast cue through SoundHandler. The ending waits for its presentation and audio before handing off to the next stage or the title. Warp completion can choose an explicit destination and still shows that stage’s intro.

## Audio

All gameplay audio uses non-positional playback at default gain. SoundHandler caches the generated effects. Coin, 1 UP, and timer tick share one voice, with 1 UP protected from interruption. During level clear, the ticker temporarily takes over the second pulse while the rest of the jingle keeps playing.

Music, effects, and transition jingles route through `NES_Mix` at 0 dB before reaching `Master`. The bus applies a 90 Hz high-pass and an 18 kHz low-pass. Use the **Bypass** button on `NES_Mix` in Godot's Audio panel to hear the same mix with both filters off.

MusicHandler starts background music when gameplay is revealed. Area transitions restart the destination track, including a transition within the same area. Same-area movement without a transition keeps playback running. Starman overrides the area's track on the update after pickup. At three counts remaining, the current area's track restarts with 63 active ticks of protection left. Pause freezes playback. Death, completion, and level shutdown stop the background loop. The title backdrop is silent.

LevelTimer latches hurry mode on the 100-to-99 decrement or when a timed attempt starts at 1–99. MusicHandler plays the 168-tick warning once, then chooses the fast loop. Starman pickups and music-window expiry during the warning update the pending loop and let the warning finish. During the warning, action and reward effects take over their respective pulse stems while the other music voices continue. Fast loops use the NES note-length tables with the same note frequencies and playback rate. The level's hurry mode carries across area travel. Accepted completion, warp, and death stop the warning or loop. Each new attempt initializes its own timer and music.

Timed coin rewards share the QuestionBlock implementation across question, hidden, and both reward-brick variants. BlockReward holds authoring data (Coin, Timed Coins, or Power-Up); existing PackedScene reward assignments remain compatible. Each block owns its started/remaining state and bounce depletion decision. BaseLevel advances registered timers through weak references so camera activity suspension cannot extend a loaded block's window. Area unload snapshots the timer, and tree pause freezes level processing.

Green Koopa currently inherits BaseEnemy directly with the shared Walking state. Walking optionally mirrors asymmetric artwork when direction changes; Goomba retains its default facing behavior. Koopa shares the 14×16 terrain body. Goomba and Koopa opt into a bottom-center floor probe on their Walking nodes. The probe samples current terrain before movement. Fractional vertical movement carries the fall until that point reaches support. On the first supported tick after falling, walking Green Koopa faces the player before moving horizontally. Goomba keeps its current direction on landing. Walking enemies use the rectangle for wall contact. Ordinary rolling shells share the center-foot floor check and fractional fall, then check a single side point before moving. The point sits eight pixels from center in the stored direction and four pixels above the feet. A blocked side reverses the shell before its horizontal step. A kicked shell rolls at 3 pixels per tick and subtracts 1.5 while unsupported. On the first supported tick it resumes its stored speed and skips the side check. Idle and stunned shells retain their rectangle sweep. A rolling shell launched by a block uses its dedicated launch path through the first roll tick. Its player-contact area is 12×12 while walking and 10×6 in the idle, moving, and stunned shell states. Its two walking frames follow the global eight-tick animation phases. EnemyLayout source 2 creates its generic enemy-category spawner, with all three theme textures. Walking Mario contact uses the shared damage/stomp check. A successful stomp enters ShellIdle without permanent defeat, stops horizontal motion, and awards 100 points through the shared enemy score-popup helper. ShellIdle reuses zero-speed Walking for gravity/terrain handling; idle shell contact kicks it away from Mario, while a moving shell can damage him or be stopped by a stomp. ShellMoving checks current enemy boxes on odd physics ticks before advancing, using the same enemy box sizes as projectiles. It clips horizontal endpoints to the playfield and skips contact if either actor is outside the reference eligibility bounds. Each Goomba in a spawned pair is checked separately. ShellMoving delivers EntityHit shell attacks and awards chains on permanent defeat. Its overlap latch records accepted reactions only, allowing a temporarily rejected hit to retry while contact continues. An idle shell wakes after 336 active physics ticks, with globally phased warning poses over the final 84 ticks. Waking restores full-height artwork, shared walking animation, and normal damaging/stomp contact; pause freezes the sequence.

### Painted spawn ownership

`EntitySpawner` is the single placement implementation for painted enemies and power-ups. Each placement attempts activation once per area load; a rejected attempt is consumed, and camera re-entry does not retry it. Area reload reconstructs placements under the existing persistence policy. BaseLevel retains public spawn-slot authority through LevelSpawnRegistry; the area activates placements and independently cleans up their live actors.

### Nested entity activity

BaseEntity owns one EntityActivity helper for cached geometry, processing-state records, and activity-animation suspension. Its public suspension methods/flags remain on BaseEntity, which also combines suspension reasons for the state machine, synchronizes controller input, registers with the area, and owns shutdown. The helper receives the entity per call rather than retaining a strong owner reference; it adds no scene node or processing callback. BaseEntity suspension visits its internal nodes and stops at nested BaseEntity roots. The same boundary applies to animation suspension and cached activity geometry. The area tracks each entity independently: sleeping a painted spawner does not freeze its moving actors, and waking the spawner cannot restore processing over a child's independent suspension. SpawnableEntity actors retain shared offscreen removal and release their category slots when freed. Area/title/transition lifecycle paths suspend entities explicitly; tree pause still freezes gameplay. New entity types inherit these boundaries without individual sleep/cleanup code.

### Consecutive enemy stomps

BasePlayer owns its airborne stomp chain. Accepted Goomba stomps and Koopa walking/moving-shell stomps award 100, 200, 400, 500, 800, 1000, 2000, 4000, 5000, 8000, then repeated 1-Ups through the shared enemy popup/reward helpers. Rejected hits do not advance it. Landing in shared player movement or beginning death resets it; pause preserves it. Shell defeat chains remain independent. This intentionally omits the NES short-lived StompTimer scoring modifier.

Shell kicks use Mario's current stomp-chain count without incrementing it: 400, 500, 800, 1000, 2000, 4000, 5000, 8000, then repeated 1-Ups. Landing therefore restores the normal 400-point kick. Remaining wake time overrides this calculation at 22-42 ticks (500) and 1-21 ticks (1000), mapping the reference interval counts onto the existing fixed 336-tick wake sequence. Kicking a moving shell is rejected. Each Koopa owns a 12-physics-tick (0.2-second) grace window after an accepted stomp. During that window, fresh contact with that same moving shell can stop it and bounce Mario without descent. A stomp refreshes grace; a kick does not. Other actors receive no grace, and the overlap latch still requires separation. Pause freezes the countdown; waking or permanent defeat clears it. This is a deliberate shell-local rule rather than the NES shared player timer.

### Koopa block stuns

GreenKoopa accepts block_bump through the shared BlockHitReceiver without permanent defeat. ShellStunned starts a recoverable launch with a two-pixel lift and its first movement step in the hit update. An unobstructed hit moves the body five pixels upward while the old artwork holds its position. The next update reveals the upside-down shell aligned to the terrain body’s feet and resets sprite interpolation. The launch then uses Walking physics. Landing enters ShellIdle and starts its existing 336-tick recovery window; kicking is allowed before landing and preserves upside-down presentation. Each new valid bump reapplies the launch and awards 100 points without advancing Mario's stomp chain. Bumping a moving shell preserves ShellMoving and its enemy-hit chain, sets its stored roll speed to 60 px/s away from Mario, and turns its artwork upside-down. The hit lifts the shell two pixels and vertical launch motion starts on the next tick. During that launch it drifts at 30 px/s opposite its stored direction and uses the shared NES fractional vertical step relative to its launch height. The shell keeps its drift on the update that reaches a surface, then confirms support and resumes its stored roll on the next update. For the struck block, a bottom-center probe qualifies support during the moving shell launch. A temporary collision exception lets the shell pass a corner its center misses. The leading side probe follows the stored direction and can turn the shell while it falls. The exception ends when the body clears the block or leaves ShellMoving. Other terrain uses the shared body collision. A subsequent kick restores 180 px/s; a stopping stomp restores the upright shell. Waking restores upright walking and global animation. Orientation is Koopa-owned; movement, gravity, cleanup, scoring, and contact continue through shared paths.

`BlockLaunchPresentation` shares the hit-tick sprite hold and next-update reveal between Goomba's block knockout and Koopa's ShellStunned state. The helper tracks the sprite anchor and resets interpolation during the handoff. Each state chooses the artwork, reveal position, and launch motion. A moving shell flips on contact and keeps its own launch timing.

### Mario forms and contact profiles

Mario remains one scene/actor with the existing Body, state machine, camera/level references, and movement cadence. Its Form child uses MarioFormController to apply a MarioForm Resource. assets/player/forms/small.tres and super.tres supply idle/walk/skid/jump/crouch/climb art, intermediate growth art where available, presentation offset, standing/crouched enemy-contact profiles, and capability data. The controller rewrites instance state textures and duplicates animation clips locally; shared source animations and other Mario instances are not modified. Reconfiguration preserves the current state, body position, and active animation phase. Dead uses existing Small death art and its Small offset.

Luigi inherits the Mario player scene, including its movement nodes and states. He supplies his own Small and Super form resources and death sprite. Growth, damage, and mushroom collection use the player's configured form pair. The inherited movement settings give both characters the same physics and can be overridden in Luigi's scene.

Mario and Luigi share a Fire form resource with the same contact profiles and movement capabilities as Super. `ignite()` accepts Super and holds the player and level while the global animation clock selects prebaked textures from the area theme. `PlayerPalette` replaces the sheet while preserving the current atlas cell. The normal Fire texture returns at release or cancellation. Fire damage uses the existing shrink sequence and the active character's Small form. Set **Player Start Configuration** to `assets/player/forms/fire.tres` to preview Fire artwork in a standalone level.

In Fire form, a fresh Run press launches a fireball after player movement. Grounded throws round the feet Y to the logical floor height so the body safe margin does not shift the shot up a pixel. **Max Fireballs** on the player defaults to two and includes projectiles in their burst animation. The player launcher cycles through the slots and ignores a press when the next slot is occupied. The projectile lives in the active area's `WorldObjects` and owns its motion, terrain probe, and burst. It releases its slot at the left, right, or bottom edge of the screen or after the burst. A shot above the camera keeps moving and occupies its slot.

An accepted launch starts the shared `FireThrowPose`. It uses the grounded walk cadence, carried into the air on takeoff. The pose draws the full throw sprite when horizontal input and speed are neutral, or replaces the top 24 pixels and keeps the movement pose's feet. The ordinary movement state and animation continue beneath the overlay.

The flagpole shaft uses a two-pixel-wide projectile collider. Fireballs sweep their horizontal movement so they burst at the visible shaft even if a single step crosses it. Mario grabs the pole through its climb detection, and the pedestal remains solid terrain.

After terrain and screen-edge checks, a traveling fireball tests enemy bounds on alternate ticks. It visits overlapping enemies in descending spawn slot order and delivers a `fireball` hit with the shooter as the attacker. Contact starts the burst independently of the enemy's damage response. Goombas and Koopas enter their shared knockout path immediately, including Koopas in any shell state. The enemy owns the smack cue and popup, and schedules 100 points for a Goomba or 200 for a Koopa after five ticks. Fireball rewards are independent of stomp and shell chains.

For horizontal edge contact, the enemy's artwork origin may be up to seven pixels left of the view or as far right as its final visible pixel. Both horizontal hitbox endpoints clamp to the visible pixel span, and touching endpoints count as contact. A single fireball can hit multiple eligible enemies on the same tick.

The title menu selects Mario for `1 PLAYER GAME` or Luigi for `2 PLAYER GAME`. Select cycles the rows, and Start confirms. TitleFlow carries the selection through the start transition. GameHandler stores the typed run character and chooses the Luigi scene when loading a playable level for that run. Death restarts and stage loads retain the run character, and pipe travel keeps the existing actor. Returning to title clears the selection and restores the Mario option.

The HUD and level intro read the run character from GameHandler, so they can refresh independently of the player scene. The HUD shows the character's name above the score during gameplay and on transition cards that display the HUD. The level intro uses the character's Small idle artwork for the lives portrait.

`BaseLevel.player_start_configuration` is an optional resource passed through `BasePlayer.configure_start()` before tree entry. The standard Mario Small and Super resources select the corresponding form for either character. Normal 1-1 uses Small Mario. For a standalone Luigi preview, select his scene as the level's Player Scene. A startup preview does not set GameHandler's session powerup_form or introduce form persistence.

Super uses its standing 12x24 EnemyHurtbox and a centered 16x32 sprite at (0,-15), retaining the existing Small art's bottom alignment at Body Y=+1 (last opaque row begins at Y=0). The shared 11x14 body handles lower-side contact while MarioTerrain supplies floor probes and Super's standing head and side probes. Crouch selects the short probes and 12x12 contact profile, persists through jumps, and follows grounded input filtering. Uncrouching immediately restores standing contact/art and applies fixed-order one-pixel side push-out. Super uses its separate reference-derived jump cue. Area arrival clears posture without replacing the actor or form. Growth, Super damage/shrinking, and ordinary/alternate brick breaking are implemented; the detailed ownership and remaining reference limits are documented below.

Game selects one `ShadowStyle` resource for the title and all stages: Soft, Crisp, Outer Blur, or null. Levels do not expose style overrides. `SharedShadowComposer` owns render routing in both Game (F5) and standalone levels (F6); standalone levels create it under Systems without moving gameplay nodes and read the saved Game style/master toggle without instantiating a second game. Decorations render behind the composite and never enter its silhouette mask. Null styles route contributors directly and disable both offscreen updates. Game's existing master toggle still suppresses any selected style. The compositor releases its level and routed canvas items on level tree exit, before deferred deletion; detached areas are never refreshed by the persistent compositor.

`draw_order.gd` defines absolute priorities within the gameplay canvas. Back to front, it orders the behind-world presentation, terrain and ordinary world objects, available items, reward effects, enemy sprites, HUD, the normal player, and fireballs including their bursts. The backdrop, area color, and decorations draw behind the gameplay canvas content. Rising coins and score popups share the reward priority. Enemy priority applies to the sprite, and area-owned popups keep the reward priority. A power-up keeps its block crop and behind-world priority while emerging, then draws above ordinary blocks when available. The compositor applies the same priorities with and without shadows.

Camera following separates horizontal movement from positional correction. BasePlayer accumulates head-escape and physics-recovery offsets; Mario also records Super terrain push-out. LevelCamera subtracts those offsets when measuring new forward progress, while using the real position for screen thresholds. Blocked side contacts do not contribute scroll; valid ledge movement still does. Pipe destinations and death respawns request sprite-origin screen X=56 (body X=64), clamped to camera world bounds. Ordinary area endpoints use the camera's full-speed follow position.

BaseLevelArea owns a bounded `Background` ColorRect and exported background_color. Editor refresh derives its rectangle from the area's camera world limits and visible height; runtime render synchronization refreshes the same geometry. SharedShadowComposer routes the active background behind decorations and outside the shadow silhouette capture, preserving scene ownership. Inactive areas unload/recreate the fill through existing runtime templates; the area's colour is reapplied on synchronization. The default is transparent.

Game owns an input-ignoring, viewport-filling black `Backdrop` ColorRect behind SharedShadow and all gameplay/UI content. It is outside silhouette capture and does not cast shadows. Transparent area backgrounds expose this black fill during F5; standalone F6 retains the engine viewport default where no area colour is supplied. The project clear-colour setting is not overridden.

Ground reversal chooses friction using Mario's previous facing before updating his facing for the tick. Slide checks low speed before braking, resets qualifying momentum, and accelerates in the requested direction during the same movement step. This matches the audited ordinary reversal curves without adding another body integration. Landing/re-jump profile selection is qualified by 20 reference-derived flat-ground cases across Small/Super and both directions, including immediate/delayed takeoff and landing-contact input gates.

Super standing head collision combines an underside sweep with current-probe occupancy checks for diagonal corner entry. It uses actual upward displacement even if gravity has already reversed the next velocity. The standing head reaction requires tile-relative Y phase >=4; below that threshold, side checks remain active. An accepted block bounce sets vertical speed to zero, while a solid/rejected contact reverses it to +60 px/s (+1 pixel per 60Hz tick), without snapping position. Both use the shared bonk effects. Short-body/side-probe ownership and hidden-block underside handling remain separate.

MarioTerrain point probes query both the default canvas (TileMap ground bodies) and the player’s CanvasLayer (entity bodies under Game). This applies to occupied-head detection and standing side checks, so F5 and standalone levels share collision behavior. World-coin probes retain their separate canvas-aware collection path.

Ordinary/alternate bricks use BrickActiveState to choose bounce or terminal break from Mario’s can_break_bricks capability. Broken hides the brick immediately, retains a temporary solid cell through the following player contact pass, then retires collision and queues deletion. An optional block-selected vertical response is captured by BonkAction and applied by the player, applying the selected response across short/standing head paths; ordinary brick breaking replaces only the integer vertical speed with -2 while preserving fractions. Reward bricks keep QuestionBlock behavior. Broken also awards 50 points once without a score popup and creates area-owned, non-colliding debris. Four themed 8×8 fragments use two gravity trajectories, mirrored horizontal travel, and the shared animation clock for flips. The debris owns its non-positional shatter voice, survives brick deletion, pauses with gameplay, and frees below the visible screen. SoundHandler loads the cached shatter cue at default playback gain/pitch; no live noise-channel renderer runs during gameplay. Coin-above and shatter-specific victim changes remain deferred.

Accepted BonkAction block reactions start a 16-physics-tick gate. Subsequent interactive reactions are rejected during the gate while solid contact remains active. Brick breaking uses the reference -2 integer response with fractions retained and a temporary solid cell. Ordinary collision reverses it only while the head still samples that cell; row-edge escapes can retain ascent. Negative shatter responses preserve the current jump-gravity selection.

Player Motion groups separate HorizontalMovement, AirMovement, and VerticalMovement components. VerticalMovement owns airborne integer/fractional integration plus post-movement speed commitment. Body.velocity publishes the composed speed and accepts impulses. BasePlayer keeps the single body movement call and final collision-response ordering. The 60Hz reference path uses byte fractions and integer displacement, with the prior float calculation retained for non-NES gravity/timing/cap configurations.
