# Level camera

TestLevel uses LevelCamera on its Camera2D. BaseLevel calls follow_target after player state physics and before its horizontal screen clamp. It follows the moving Body, not the stationary entity root. Camera2D processes on physics ticks, has no smoothing, and receives an immediate scroll update before the clamp reads the screen center.

The requested behavior is original SMB right-only scrolling: no backward scrolling and no vertical tracking. It begins after the target's screen-relative sprite-left coordinate reaches 80 pixels; before 112 pixels, it scrolls at half the player displacement. At 112 pixels and beyond, it scrolls the full step. The camera cannot advance beyond the right world edge. Mario can move left within the current view but cannot return to areas that have scrolled away.

LevelCamera exposes Follow Enabled, World Left/Right, Scroll Start, Full Speed Start, and Target Origin Offset. Defaults are -128/768 world bounds and 80/112 thresholds. Target Origin Offset is 8 world pixels because Mario's Body origin is horizontally centered, while the reference tracks sprite-left position. These thresholds target the current 256-wide, 1x, unrotated camera. Zoom-aware width is used for world limits, but the NES threshold proportions are not automatically rescaled for other view sizes.

The camera uses fractional target displacement so a steady 2.5-pixel step remains 2.5 rather than alternating between 2 and 3. The early zone uses a continuous half-speed factor. These are deliberate smoothness adjustments to the reference's integer-step scrolling, preserving the 80/112 thresholds and right-only behavior. Rendering still uses the 256-by-240 pixel-art viewport and physics updates; this does not add render interpolation or guarantee smooth frame pacing on every display. It does not reproduce NES fractional integration, previous-frame rendering order, SideCollisionTimer scroll suppression, moving-platform scroll forces, or every game-mode lock. Reference: ScrollHandler in https://gist.github.com/1wErt3r/4048722 . Solid walls already cancel body movement in Godot. Keep the camera's transform and smoothing at the authored values for this mode.

TestLevel is restored to its original one-screen test size: cells 0 through 15, two rows at Y=13/14, world X=0 through 256. Camera center is (128, 120) and PlayerSpawn is (40, 208). The scene overrides World Left/Right to 0/256; scrolling logic and thresholds remain available, but there is no scroll room at the current viewport width. The scrolling test builds its own 896-pixel fixture. Existing block markers are unchanged. BaseLevel owns explicit Players/PlayerSpawn and EntityLayout paths; preserve those paths when organizing scenes.

Camera follow tests cover thresholds, slowed/full fractional steps, no backward/vertical scrolling, the right limit, and a live run across the stage. Existing camera-boundary tests disable follow to isolate the clamp. Jump tests create their own floor gap for ledge behavior. There is still no automatic death or respawn.
